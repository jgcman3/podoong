# 가족 거주지역 저장

2026-10-27: 글로벌 가족 거주지와 국가·지역별 커뮤니티 연결을 지원합니다. 249개 국가·지역을 선택할 수 있으며, 상세 지역 선택은 현재 한국에서 제공합니다.

## 화면과 이용 방식

**우리 가족 → 가족이 사는 곳**에서 `국가 / 지역 → 시·도 → 시·군·구 → 읍·면·동`을 드롭다운으로 선택해 저장합니다. 상위 지역을 바꾸면 하위 선택은 초기화되며, 국가만 저장할 수도 있습니다. 해외는 우선 국가까지 저장하며 도시·동네는 각국의 공식 지역 목록이 준비되면 추가합니다. 국가를 변경하면 기존 지역 코드를 지웁니다. `거주지역 삭제` 후 저장하면 등록 정보를 지웁니다. 상세 주소·좌표는 수집하지 않습니다.

같은 가족의 모든 아이가 공통 거주지역을 사용합니다. 가족 소유자만 수정하며 다른 가족 구성원은 조회합니다. 공개 커뮤니티에 거주지역을 자동 게시하지 않습니다.

## 공식 지역 목록

[행정표준코드관리시스템 법정동코드 전체자료](https://www.code.go.kr/stdcode/regCodeL.do)를 2026-10-15 내려받아, 존재하는 읍·면·동 **5,067개**를 사용했습니다. 폐지 지역과 리 단위는 제외합니다. 행정동이 아닌 **법정동 기준**이므로 예를 들어 역삼1동·역삼2동은 역삼동으로 선택합니다. 세종과 `수원시 영통구`처럼 단계가 다른 지역도 목록으로 제공합니다.

원본 출처·내려받은 날짜·UTF-8 원문 SHA-256은 [korean-regions-source.json](korean-regions-source.json)에 기록합니다. 화면 목록은 `src/features/family/korean-regions.json`, DB 목록은 마이그레이션 `015`에 포함됩니다. `016`은 원문의 대신면 항목에 붙은 후행 공백을 정리하며, 가져오기 스크립트도 항목별 공백을 제거합니다. API 키나 실시간 외부 호출은 필요하지 않습니다.

갱신 시 공식 ZIP의 CP949 텍스트를 UTF-8로 변환한 뒤 `node scripts/import-korean-regions.mjs <원문.txt> <YYYY-MM-DD>`로 화면 목록과 출처 메타데이터를 생성합니다. **적용된 마이그레이션은 수정하지 않고** 새로운 마이그레이션으로 DB 목록도 갱신해야 합니다. 사용 중인 코드는 삭제하지 말고 비활성화하며, 이후 행정구역 개편 시 커뮤니티 연결의 이전 정책을 결정합니다.

## PostgreSQL 저장과 권한

`014`의 가족 거주지역 필드에 `015`가 국가 코드(`residence_country_code`)와 지역 코드(`residence_region_code`)를 추가합니다. `016`은 한국 전용 DB 제약을 국가별 코드와 계층을 담을 수 있는 구조로 확장합니다. 가족은 `(국가 코드, 지역 코드)` 복합 외래 키로 지역을 참조합니다. 국가·지역 목록은 공개 읽기만 허용하며 일반 사용자가 추가·수정할 수 없습니다.

`save_family_residence_region` RPC는 활성 계정·가족 소유권·수정 버전을 확인하고, 활성화된 국가의 선택 가능한 지역으로부터 명칭을 직접 조회해 저장합니다. 비활성 지역과 비활성 상위 지역에 속한 동네는 저장하지 않습니다. 임의 명칭이나 미등록 코드의 저장은 허용하지 않습니다. 삭제 시 국가·지역 코드와 명칭을 모두 NULL로 처리합니다. 감사 로그에는 지역 본문을 넣지 않습니다.

후속 서비스는 `context.family`의 국가·지역 코드를 활용합니다. 동네별 커뮤니티 자동 연결은 `017`에서 구현합니다. 시군구·읍면동 게시판과 국가 주제 게시판의 [공유 범위](community-home-boards.md)를 참고하십시오. 국가만 설정하면 해당 국가의 주제 게시판만 연결하며, 시군구·동네 게시판은 검증된 지역 코드가 있을 때만 연결합니다.

## 해외 확장을 위한 DB 구조

`016`의 국제 지역 계층에 `027`의 국가 목록과 국가 단독 저장을 추가했습니다. 국가별 지역 자료는 다음 구조로 확장합니다.

| 테이블·필드                              | 역할                                                                         |
| ---------------------------------------- | ---------------------------------------------------------------------------- |
| `residence_countries.code`               | 대문자 2자리 국가 키. 249개 ISO 국가·지역 등록·활성화                                |
| `residence_countries.enabled`            | 새 국가는 기본 비활성. 데이터 등록과 서비스 공개를 구분                      |
| `residence_regions.(country_code, code)` | 국가 범위의 고유 지역 키. 다른 나라의 같은 코드는 충돌하지 않음              |
| `parent_code`, `parent_level`, `level`   | 같은 국가 내 상위 지역과 깊이. 국가별로 다른 단계 수 지원                    |
| `kind`                                   | `province`, `state`, `county`, `city`, `neighborhood` 등 국가별 지역 종류    |
| `community_scope`                        | 시군구·동네 게시판 역할. 실제 행정구역 종류·깊이와 별도로 국가별 설정(`017`) |
| `selectable`, `active`                   | 가족 거주지로 선택할 수 있는지, 현재 유효한지 구분                           |

한국 동네는 기존 10자리 법정동 코드를 유지합니다. DB의 지역 코드는 최대 128자의 문자열로 숫자·영문을 모두 허용하며, 코드 앞자리로 세계 공통 계층을 추정하지 않습니다. 한국의 `province:11`, `district:11680`은 목록에서 파생한 그룹 키이며 공식 법정동 코드가 아닙니다. 한국 그룹 → 동네 관계를 DB에도 연결합니다. 부모는 동일 국가의 한 단계 위에 있어야 하므로 국가 간 연결과 순환 참조를 막습니다.

RPC의 `p_country_code`는 한국 호출과의 호환을 위해 기본값이 `KR`이고, 서버 액션은 사용자가 선택한 국가를 전달합니다. 국가 단독 저장은 `save_family_residence_country`에서 동일한 소유권·활성 계정·버전 검증을 수행하고 지역 코드와 명칭을 비웁니다. 해외 국가를 추가해도 RPC와 가족의 복합 참조를 그대로 사용합니다. 지역별 가족 조회를 위한 복합 인덱스도 둡니다. 이후 커뮤니티 연결은 지역 명칭 대신 국가·지역 키를 사용해야 합니다.

### 추후 국가별 지역 목록 추가 순서

1. 신뢰할 수 있는 국가별 지역 자료와 출처·갱신일을 준비하고, 이미 등록된 국가 코드에 연결합니다.
2. 국가별 안정적인 지역 키·명칭·부모·깊이·종류를 등록합니다. 동네 자료가 없는 곳은 서비스 정책에 따라 도시 같은 다른 단계를 선택 가능하게 지정할 수 있습니다. 등록 후에도 기존 키를 재사용하지 않으며 개편된 지역은 비활성화와 연결 이전 정책으로 관리합니다.
3. 해당 국가의 목록 조회·입력 검증을 추가합니다. 현재 한국 전용 JSON과 10자리 입력 검증을 다른 나라에 그대로 적용하지 않습니다.
4. 해당 국가의 지역 저장·조회·권한 검증 후 상세 지역 선택 화면을 공개합니다.

국가 추가 자체에는 새 컬럼이나 국가별 전용 테이블이 필요하지 않습니다. 해외 상세 지역 데이터 수집은 후속 작업입니다. 국가를 임의 텍스트로 저장하거나 자유 입력 도시 이름으로 게시판을 합치지 않습니다.

## 검증

단위 검사에서 코드 형식, 읍·면·동, 세종 및 시·구 계층을 확인합니다. DB 검사는 위조 코드·권한·수정 충돌·삭제를, 브라우저 검사는 단계별 선택·재접속·아이 전환·가족 분리·모바일 화면을 검증합니다.

2026-10-15 연결된 `mkybqrhjrpouxmxizmpt` 프로젝트에 `015`를 적용했습니다. 단위 테스트 55개, pgTAP 254개와 먹이기 정리 검사 10개, 가족 거주지역 브라우저 동선 1개가 통과했습니다. PC·390px 모바일 화면을 확인했으며 린트·타입 검사·빌드, 지역 목록을 포함한 18개 주요 테이블의 로컬 백업 복원도 통과했습니다. 테스트용 가족 자료는 로컬 DB에서만 생성·정리했습니다.

해외 확장 대비 `016`도 같은 프로젝트에 적용했습니다. 기존 한국 코드와 가족 연결을 보존하며 실제 해외 국가는 추가하지 않았습니다. 가상 국가 자료를 사용하는 로컬 DB 검사에서 국가별 코드 중복, 4단계 계층, 영문 코드 저장, 국가 간 잘못된 부모 연결·순환·미공개 국가 차단을 확인했습니다. 최종 단위 55개·pgTAP 279개·먹이기 정리 10개·브라우저 동선 1개, 린트·타입 검사·빌드 및 주요 테이블 19개의 백업 복원이 통과했습니다.

## 국가 목록 출처 및 갱신

국가 키는 [ISO 3166-1](https://www.iso.org/iso-3166-country-codes.html)의 두 자리 코드입니다. 목록은 [iso-codes 데이터](https://github.com/sailfishos-mirror/iso-codes/blob/master/data/iso_3166-1.json)를 2026-10-27 내려받았습니다. 한국어·영어 표시 이름은 Node의 `Intl.DisplayNames`로 생성한 정적 `countries.json`을 사용해 서버와 브라우저 표시 차이를 방지합니다. 국가 코드 검증 목록은 `country-codes.json`, DB 스냅샷은 `027`입니다. 갱신 시 세 목록을 함께 검증하고 적용된 마이그레이션은 수정하지 않습니다.

글로벌 확장 검증: 단위 99개, DB 411개 및 정리 검사 10개 통과. 국가 변경 시 이전 한국 지역 제거, 국가별 주제 게시판 연결, 지역 미설정 시 동네 게시판 미노출, 수정 충돌과 다른 가족의 변경 차단을 검증합니다.

## 해외 주소 공동 등록 (2026-10-28)

한국은 기존 공식 지역 선택을 유지합니다. 해외는 국가 다음에 시도(주/지역), 시군구(도시/구역), 읍면동(동네)에 해당하는 이름을 필수 입력하며 추천 목록에서 기존 값을 선택할 수 있습니다. 상위 이름을 변경하면 하위 입력은 비워 서로 다른 지역을 잘못 결합하지 않도록 합니다.

가족관리자가 주소를 저장하면 `global_residence_places`에 공용 지역 이름만 등록합니다. 가족/아이/사용자 정보는 이 목록에 포함하지 않습니다. 국가·정규화한 시도·도시·동네 조합을 유일 키로 삼아 동시 입력, 대소문자 및 연속 공백 차이로 인한 중복 등록을 막고 최초 표기와 ID를 재사용합니다. 서버는 소유자와 주소 버전을 검사하며 다른 가족은 목록 조회만 할 수 있습니다. 등록 목록은 상위 지역별로 불러옵니다.

해외 동네 생활 신청은 국가·시도·시군구로 그룹을 나눕니다. 같은 이름의 도시라도 주/도가 다르면 다른 그룹입니다. 동네 이름은 세부 지역 정보로 저장합니다. 기존 국가만 저장한 가족은 지역을 입력한 뒤 신청할 수 있습니다. 마이그레이션 050.
