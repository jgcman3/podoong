# 다음 먹이기 웹 푸시

작성일 2026-10-29

## 제공 범위

아이 이름 메뉴 → 알림 설정에서 한 가지 핵심 알림만 제공한다. 마지막 모유·분유·이유식의 **시작 시각**부터 사용자가 선택한 간격(기본 3시간)이 지나면 알린다. 먹인 시간이 선택 항목인 분유·이유식도 포함한다. 모유 수유가 진행 중이면 알리지 않는다. 간격은 의료 권고가 아닌 보호자가 선택한 설정이다.

- 이 기기에서 알림 켜기: 사용자 동작으로 브라우저 권한을 요청하고 기기를 등록한다. 자동으로 권한을 요청하지 않는다.
- 설정 저장: 계정의 알림 간격과 야간 설정을 변경한다. 같은 계정의 다른 등록 기기에도 적용한다.
- 이 기기 알림 끄기: 해당 기기의 구독만 삭제한다. 로그아웃 시에도 해당 기기의 서버 구독을 해제한다.
- 밤에는 쉬기: 계정 시간대 기준 22:00–07:00에는 발송하지 않는다. 지난 알림을 아침에 한꺼번에 보내지 않는다.

## 기기와 접속 조건

서비스 워커·Push API는 HTTPS가 필요하다. 개발용 `http://localhost`·`http://127.0.0.1` 예외와 달리 `http://192.168.45.85:3187`은 휴대폰에서 보안 접속으로 인정되지 않는다. 아이폰/iPad는 iOS/iPadOS 16.4 이상에서 홈 화면에 추가한 웹앱을 열고 알림을 허용해야 한다. 지원 여부·권한 거절·설치 필요·HTTP 상태에 따라 화면에 실제 조건을 안내한다. HTTPS 접속을 마련하기 전에는 LAN 아이폰 푸시 수신을 검증한 것으로 간주하지 않는다.

## 발송과 권한

`055` 마이그레이션의 구독·발송 이력은 RLS로 보호한다. 브라우저는 자신의 기기만 등록·삭제할 수 있고 직접 쓰기는 차단한다. 발송 큐의 조회·처리는 서비스 역할만 허용한다. 사용자당 기기는 최대 5개다. 브라우저 제공자의 HTTPS 푸시 서버만 허용하며 임의 URL·내부망 주소로 요청하지 않는다.

Supabase Cron은 매분 DB를 확인하며 발송할 자료가 있을 때만 `feeding-push` Edge Function을 호출한다. 전용 무작위 인증 토큰은 Vault에 보관하고, VAPID 비밀키는 Edge Function 비밀 설정에 저장한다. 함수는 JWT 대신 전용 토큰을 검증하므로 `verify_jwt=false`가 의도된 설정이다. `claim_feeding_push` 자체도 서비스 역할과 올바른 토큰이 모두 필요하다.

각 기기·마지막 식사에 한 번 발송한다. 잠금과 임대 토큰으로 동시 실행을 구분하고 일시 오류는 최대 3회 시도한다. 발송 직전에 새 식사·권한 회수·설정 변경·탈퇴 요청을 다시 확인한다. 만료된 구독(404/410)은 삭제한다. 예정 시각에서 30분이 지난 알림은 발송하지 않는다. 전송 대기 TTL은 5분이다. 네트워크 응답 소실 시 재시도가 발생할 수 있으므로 알림 태그도 아이별로 동일하게 지정한다.

알림 본문에 아이 이름·사진·식사량을 넣지 않는다. 서비스 워커는 페이지나 아이 자료를 오프라인 캐시하지 않는다. 알림을 누르면 같은 서비스 주소의 오늘 화면을 열고, 이미 열린 창이 있으면 재사용한다. 발송 이력은 최대 30일 보관하며 내용·기기 키·푸시 서버 오류 본문을 로그에 남기지 않는다.

## 운영 설정

1. `node scripts/generate-web-push-keys.mjs`로 `.env.push.local`을 한 번 생성한다. 파일은 Git 제외·소유자만 읽기/쓰기가 가능한 권한으로 보관하고 키를 재발급하지 않고 재사용한다.
2. `supabase secrets set --project-ref <서울 프로젝트> --env-file .env.push.local`로 키를 등록한다.
3. `supabase functions deploy feeding-push --project-ref <서울 프로젝트> --no-verify-jwt --use-api`로 함수를 배포한다.
4. 서비스 역할/운영자 DB 연결에서 `configure_feeding_push(<공개 키>, 'https://<프로젝트>.supabase.co/functions/v1/feeding-push')`를 호출한다. 공개 키·토큰·Cron을 연결하며 비밀값을 출력하지 않는다.
5. HTTPS 앱의 알림 설정에서 기기를 등록하고 실제 휴대폰의 백그라운드 수신을 확인한다. 브라우저 권한과 절전·집중 모드에 따라 OS 표시가 제한될 수 있다.

## 검증

긴 수면 편집의 브라우저 재현 검사에서 종료 시각 입력으로 10시간 15분 저장·재편집을 확인했다. 수면 입력과 표시에서는 분 미만을 제외하고 시간·정수 분만 사용한다.

알림 DB 검사는 접근 권한·옵트인·선택적 먹인 시간·새 식사 시 취소·동시 임대·중복 방지·간격 변경 재예약·야간·권한 회수·탈퇴 요청·만료 구독을 검증한다. 단위 검사는 허용 서버·발송 응답 처리·잠금화면 문구·서비스 워커 표시와 기존 창 재사용을 확인한다. 브라우저 검사는 권한/푸시 공급자를 테스트 대역으로 분리하여 등록·설정 변경·해제와 접속 조건 안내를 확인한다. 실제 운영체제의 백그라운드 수신 검사와 구분한다.

참고: [WebKit의 iOS 웹 푸시](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/), [Service Worker 보안 접속](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API), [Supabase 예약 호출](https://supabase.com/docs/guides/functions/schedule-functions), [Web Push 라이브러리](https://github.com/web-push-libs/web-push).

서울 프로젝트에 DB·Edge Function·VAPID 설정·Cron 연결을 완료했다. 로컬 실제 Edge Runtime에서 인증된 빈 작업 200, 토큰 누락/오류 401을 확인했다. 운영 실제 발송 테스트는 실제 사용자에게 푸시가 전달될 가능성 때문에 자동 승인 검토에서 거절되었으며 실행하지 않았다. 이후 운영 검증은 구성·Cron 상태 조회만 사용했다.
