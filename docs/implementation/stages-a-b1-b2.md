# A·B1·B2 구현 현황

작성일: 2026-10-12. 사용자 결정: **Supabase 채택**. “3번까지”는 로드맵의 첫 세 단계 A, B1, B2로 해석했습니다. 이 문서는 구현과 외부 완료 조건을 구분하는 기록입니다.

## A — 범위와 설계

모바일 우선의 한국어·영어 화면을 구현했습니다. 로그인 → 동의·아이 등록 → 오늘 → 기록·일정 → 가족 초대 흐름과 전체 17개 서비스 목록을 제공합니다. 현재 범위 밖 서비스는 준비 중으로 표시합니다. 디자인 토큰은 `src/app/globals.css`의 색상·간격·곡률, 공통 레이아웃은 `src/components/shell.tsx`에 정의합니다.

| 역할               | 아이 조회             | 기록·일정 변경 | 아이 추가·초대·권한 회수 |
| ------------------ | --------------------- | -------------- | ------------------------ |
| 가족 소유자        | 해당 가족의 모든 아이 | 허용           | 허용                     |
| 편집 보호자        | 초대받은 아이         | 허용           | 불가                     |
| 조회 보호자        | 초대받은 아이         | 불가           | 불가                     |
| 다른 가족·미로그인 | 불가                  | 불가           | 불가                     |

실제 사용자 10~15명 인터뷰, 디자인 사용성 검증, 최초 지원 지역과 콘텐츠 담당자 지정은 미완료입니다. 커뮤니티·투표는 B3이며 구현하지 않았습니다.

## B1 — 기반과 가족

Next.js·TypeScript·Supabase SQL/RPC·RLS·다국어·CI를 구성했습니다. 가족·아이 등록, 아이 전환, 7일 유효의 일회용 초대, 편집·조회 권한, 초대 및 구성원 권한 회수, 감사 이력을 구현했습니다. 초대 토큰은 DB에 해시로 보관합니다. 다른 가족과 허용되지 않은 아이 접근은 DB에서 차단합니다.

카카오·구글 기본 제공자와 네이버 `custom:naver` 로그인 요청, PKCE callback, 초대 복귀, 세션 갱신·로그아웃, 계정 연결·해제 코드를 작성했습니다. 현재 세션 JWT의 인증 시각·명시적 변경 확인·마지막 로그인 수단 보호를 적용합니다. 제공자 설정 전에는 버튼을 비활성화합니다.

**미완료:** 제공자 앱 등록·비밀키·검수, 구현한 네이버 userinfo 변환 어댑터의 실제 OAuth 호환성, 실제 세 계정 신규·재로그인·연결·해제 테스트. 버튼이나 코드만으로 세 제공자 완료를 선언하지 않습니다.

## B2 — 기록·오늘·일정·콘텐츠

수유·분유·유축 기록, 지속 타이머, 양·시간·메모·작성자, 편집·삭제, 재시도 중복 방지와 수정 충돌 처리를 구현했습니다. 오늘 화면은 빠른 기록, 미완료 할 일, 최근 수유, 예정 일정을 표시합니다. 할 일은 담당자·서비스·날짜·완료·보류 상태를 관리하며 직접 일정과 기본 준비 목록을 제공합니다.

출산 예정일·생일 변경은 권장 일정 변경안을 먼저 보여줍니다. 아이 ID·완료 항목·수동 일정·사용자가 수정한 권장 날짜를 유지합니다. 생일·예정일은 날짜, 기록 시각은 UTC로 보관하고 사용자 시간대로 표시합니다.

임신·출산·행정·산후·건강·지원 서비스는 공통 할 일과 일정으로 제공합니다. 콘텐츠 스키마는 국가·지역·적용일·공식 출처·검토자·검토일과 두 언어 번역을 지원합니다. 초기 안내는 초안으로만 저장하며 미검토 건강·지원 정보를 게시하지 않습니다. 공식 사이트 링크와 검토 중 안내를 보여줍니다.

**미완료:** 전문 콘텐츠·번역 검토 및 실제 지원 조건·기한 확정, 실사용자 공동 관리 시험. 파일 첨부·알림·커뮤니티·투표와 후속 10개 서비스는 해당 후속 단계에서 개발합니다.

## 콘텐츠 운영 절차

운영 담당자가 공식 출처와 지역·적용일을 확인해 초안을 등록하고, 검토자가 내용과 번역을 확인한 뒤 검토 메타데이터를 기록합니다. 게시 전 양쪽 언어와 개인정보 노출을 확인합니다. 게시 행에는 출처·검토자·검토일이 DB 제약으로 필수입니다. 변경 시 재검토하고, 만료·폐지된 안내는 보관 상태로 전환합니다. 자동 게시나 관리자 웹 화면은 아직 없습니다.

## 기술 결정과 검증

초기 운영 부담을 줄이기 위해 Supabase를 채택하며 DB 변경은 마이그레이션, 복수 행 처리는 트랜잭션 RPC로 관리합니다. 권한 있는 사용자 키만 서버 요청에 사용합니다. 현재 실행 환경에 맞춰 npm lockfile을 사용하며 UI는 별도 Tailwind/shadcn 의존성 없이 CSS 토큰으로 구현했습니다.

Vitest는 날짜·안전한 인증 복귀·최근 로그인 규칙, pgTAP는 가족 격리·초대·권한·기록 충돌·출생 전환, Playwright는 로컬 DB의 가입·기록·타이머·일정·두 언어·반응형 흐름을 검증합니다. 외부 로그인과 콘텐츠 검토는 자동 테스트로 대체하지 않습니다. 실행 명령은 [README](../../README.md)에 있습니다.

저장소 최초 구현으로 Git HEAD가 없어 정식 diff 기반 리뷰는 실행할 수 없었습니다. 대신 파일 기반 독립 검토를 수행하고 연속 기록 ID·담당자 권한 회수·다른 아이 충돌 업데이트·초대 복귀·최근 로그인·조회 제한 문제를 수정했습니다.
