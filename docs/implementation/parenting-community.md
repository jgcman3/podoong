# 육아 소통: 놀이터·동네 이야기·커뮤니티

수정: 2026-11-03

## 구성

- 같은 높이의 상단 탭: **동네 놀이터 / 동네 이야기 / 육아 소통**. 기본은 육아 소통이다. 모바일 탭은 아이콘·글자 한 줄, 최소 42px로 표시한다.
- 동네 놀이터(`/community/playground`): 같은 거주 동네의 가상 아기 공간. 우측 위 위치 아이콘은 우리 아이를 중앙으로 찾는다.
- 동네 이야기(`/community/neighborhood`): 같은 국가·시군구·동(해외는 주/도도 동일)의 게시글만 보여준다.
- 육아 소통(`/community/boards`): 거주 국가가 같은 게시글을 보여준다. ‘전체’는 모든 주제를 포함한다. 지역 필터와 다른 지역 보기는 없다.
- 주제: 놀이 / 육아용품 / 발달 / 훈육 / 수유분유 / 이유식 / 출산준비물 / 산후조리 / 건강증상 / 출산 / 여행. 이번 주(UTC 월요일 시작) 해당 국가의 게시글 수 내림차순으로 정렬하며 동률은 위 기본 순서를 따른다. 무게시 주제도 선택 가능하다. 배치 작업 없이 국가·작성시각 인덱스로 집계한다.
- 글에는 작성 당시 거주 시군구·동 정보를 표시한다. 해외는 주/도·도시·동네를 표시한다. 주소 원문·가족 식별자는 반환하지 않는다. 글 작성은 실제 등록된 거주지만 사용하며 외부 지역을 대신 선택할 수 없다.
- 나라 또는 동네가 설정되지 않았으면 해당 범위의 글을 쓰기 전에 거주지 설정을 안내한다. 나눔·중고거래와 지원금은 제거했다.
- 출시 전 데이터 정리: 폐지한 주제·장터 데이터는 삭제하며 이전 값으로 변환하지 않는다. 이전 범위 조회·장터 작성·프로필 전용 목록 API와 미적용 스키마 대체 경로를 제거했다. 075는 국가/동네 API와 주간 주제를 정의한다.

## 동네 친구들

- 상단 첫 탭은 가상 놀이터다. 2.5D 사이드뷰로 넓고 낮은 지평선의 평지와 깊이에 따른 작은 아기 크기·겹침을 표현한다. 별도 게임 엔진·WebSocket·실제 위치 정보는 사용하지 않는다.
- 같은 국가·시군구·동(해외는 주/도도 동일)의 만 7세 미만 아이를 대상으로 한다. 그날 입장한 아기는 공개 체크 없이 같은 동네 사용자에게 보인다. 초등 입학 여부는 별도로 수집하지 않아 현재는 만 7세 생일을 연령 기준으로 삼는다.
- 등록된 지역의 현지 날짜를 기준으로 처음 놀이터에 들어온 아이에게 좌표를 한 번 부여한다. 구역/날짜 잠금과 고유 키로 동시 접속·재접속에도 중복 좌표를 만들지 않는다. 기존 위치는 수정하지 않고 인접한 빈 슬롯에 새 아이를 배치한다. 날짜가 바뀌면 첫 접속 때 새 좌표를 만든다.
- 공간 범위는 그날 배치된 좌표의 경계로 늘어난다. 고정된 사전 인원 집계·자정 배치·전체 동네 순회·정기 작업은 없다. 이전 배치 방식의 미완성 로컬 코드와 Cron은 제거했다.
- 처음 카메라는 우리 아이를 중심으로 열며 스와이프·마우스 드래그로 둘러보며 우측 위 위치 아이콘을 누르면 우리 아이를 선택하고 중앙으로 돌아간다. 상태가 있는 아기는 바로 위에 말풍선을 표시하며 선택한 아이와 말풍선은 함께 가장 앞에 확대 표시한다. 하단에는 상태 입력칸을 바로 둔다. 표시 나이는 D+365 이전에는 D+일수, 그 이후에는 현재 연도와 출생 연도의 차이로 표시한다. 상태 입력은 놀이터 아래쪽에 작고 투명한 형태로 배치하며 이동 화살표는 두지 않는다. 출석 인원은 그날 방문한 동네 아기와 우리 아이 기준이며 `출석 N명`으로 표시한다. 화면이 보이는 동안 1분마다 현재 범위의 상태와 출석 인원을 갱신하고 화면을 떠나면 중단한다. 안내 문구·기본 인사말은 표시하지 않는다.
- 화면 주변 좌표 구간만 조회하고 실제 화면 근처의 아기만 그린다. API 응답은 최대 150명, 캐시는 카메라 근처만 유지한다. 전체 동네의 아기를 한 번에 렌더링하지 않는다. 이미 받은 범위 안에서는 이동해도 다시 조회하지 않는다.
- 공개 이름은 `가족 이름 + 공백 + 아이 이름(닉네임/태명)`을 서버와 DB가 자동으로 조합한다. 직접 입력하는 공개 닉네임은 없다. 가족/아이 이름 변경은 다음 조회에 즉시 반영한다. 공개 여부 컬럼과 저장 API의 공개 여부 인수는 072에서 제거했다.
- `parenting_playground_regions`에는 지역과 공통 시간대, `parenting_playground_positions`에는 가상 좌표만 저장한다. 원본 좌표 테이블은 인증 사용자도 직접 조회할 수 없다. 실제 위치·사진·다른 가족/아이의 내부 식별자를 응답하지 않는다. 아이 삭제 시 좌표도 삭제된다.
- 오래된 좌표는 이후 새 방문 때 인덱스로 최대 100개씩 정리한다. 별도 삭제 작업을 예약하지 않으며 서비스 트래픽이 없으면 다음 접속 때 정리한다.
- `supabase/tests/playground_arrival.test.sql`, `tests/unit/friend-world.test.ts`, 해당 화면 브라우저 검사로 방문 등록·기존 위치 보존·이름 조합·권한·이동을 확인한다.
- 다른 아이를 선택하면 인사(👋)·하트·위로(🤗) 버튼을 표시한다. 같은 아이를 400ms 안에 두 번 클릭/탭해도 인사를 보낸다. 각 종류는 아이 쌍마다 현지 날짜 기준 하루 한 번 저장하며 중복 요청은 새 이력을 만들지 않는다. 전송 중 움직임이나 위치 정보를 동기화하지 않는다.
- 하단 이력 아이콘에서 오늘 받은 인사·하트·위로만 확인한다. 아이 이름이나 상태 문구는 이력 창에 중복 표시하지 않는다. 20개씩 과거 방향으로 추가 조회하며 현재 목록은 열려 있을 때만 1분 간격으로 갱신한다. 날짜가 바뀌면 오늘 이력만 표시하므로 별도 자정 작업이 필요 없다. 송수신 아기는 같은 동네에 오늘 입장한 만 7세 미만 아이여야 한다. 다른 가족의 수신 내역과 원본 테이블은 직접 조회할 수 없다.
- `parenting_playground_reactions`는 날짜·아이 쌍·종류의 고유 키와 수신 조회 인덱스를 사용한다. 오래된 데이터는 이후 전송 시 100개씩 정리하고 아이 삭제 시 함께 삭제한다. 실시간 통신·푸시 알림은 추가하지 않는다.
- 2026-11-02 사용자 요청: 별도 요청 전까지 전체 검사와 개발 배포는 하지 않는다. 070~080 스키마는 로컬·개발 Supabase에 적용했다. 운영 DB와 앱 배포는 진행하지 않았다. 미적용 스키마 대체 경로는 두지 않는다.

## 게시글 목록과 작성

- 동네 이야기와 육아 소통은 구분선 목록을 공유한다. 태그·제목·본문 미리보기는 왼쪽, 사진 썸네일은 오른쪽, 지역·작성 시각은 아래에 표시한다. 글을 누르면 `/community/posts/[id]` 전체 페이지에서 내용과 큰 사진을 연다.
- 우측 하단 글쓰기 버튼은 하단 메뉴 바로 위에 고정한다. 모바일은 전체 화면, PC는 중앙 작성 창으로 제목·본문·카테고리·사진을 입력한다. `#태그`는 본문에 직접 쓴다. 제목에 바로 포커스하며 사진은 최대 9장까지 미리보기·제거 가능하다. 원본 용량으로 거부하지 않고 기기에서 긴 변 2048px·장당 350KB 이하 JPEG로 자동 축소한다. 브라우저가 직접 읽지 못하는 HEIC/HEIF는 `heic-to/csp`를 필요할 때만 불러와 기기 안에서 변환한다. 한 장씩 처리해 모바일 메모리를 제한하며 완료 전에는 등록을 막는다. 등록 실패 시 입력은 유지한다.
- `077_parenting_post_photos`: 기존 비공개 Storage `community-photos`에 표시용 WebP 1600px·목록용 480px를 저장한다. DB에는 경로·순서만 저장한다. 사진 조회는 로그인 및 게시글 국가 권한을 확인한 뒤 서버에서 제공한다. 삭제 시 두 파일을 기존 정리 큐로 전달하며 고아 정리는 살아 있는 첨부 파일을 제외한다.
- 관련 SQL 검사: `parenting_post_photos.test.sql`(첨부 확인·실패 롤백·국가 권한·파일 정리), `parenting_community.test.sql`(국가/동네 목록·주간 태그). 모바일 브라우저에서 미리보기·제거·등록·이미지 조회와 상세를 확인했다. 전체 검사는 실행하지 않았다.

- 휴대폰 사진 확인: 5MB 초과 PNG 및 실제 HEIC 예제로 자동 변환·미리보기·저장·상세 사진 표시를 확인했다. LAN HTTP에서 `crypto.randomUUID`가 없어도 첨부 ID는 Blob URL을 사용하므로 동작한다. 원본은 서버에 전송하지 않으며 서버는 기존 검증된 JPEG→WebP 저장 흐름을 유지한다.

## 상세·투표·댓글 (078)

- 작성 화면의 사진 아이콘 옆 투표 아이콘에서 질문과 2~6개 선택지를 첨부한다. 글·사진 메타데이터·투표는 한 DB 트랜잭션으로 저장하며 실패 시 글이 부분 등록되지 않는다. 같은 계정은 한 표만 저장하고 다시 선택해 변경할 수 있다.
- 상세는 상단 돌아가기·공유 버튼, 카테고리, 작성자, 지역·시각, 제목·본문·사진·투표·해시태그, 공감·동네 알리기·댓글 순으로 보여준다. 모바일 하단 메뉴 대신 댓글 입력창을 고정한다. 작성 당시 표시값을 저장하며 상세·댓글·답글에는 가족 이름·가족관계를 표시한다. 목록에는 작성자를 표시하지 않는다. 보호자 실명·계정 식별자는 반환하지 않는다.
- 공감은 계정/글 고유키로 중복 저장하지 않는다. 동네에 알리기는 사용자가 실제 등록한 국가·시·구·동의 동네 이야기에도 같은 글을 노출하며 재선택해 취소한다. 별도 복제 게시글·푸시·외부 전송은 하지 않는다.
- 댓글은 오래된 순 30개씩 `(created_at,id)` 커서로 조회한다. 댓글·투표·공감·동네 알리기의 원본 테이블은 인증 사용자에게 직접 공개하지 않고 권한을 확인한 RPC만 사용한다. 글 삭제 시 관련 데이터도 함께 제거한다.
- 공유는 글 상세 URL이다. 로그인 및 동일 국가 열람 권한을 유지하며 비로그인 방문은 로그인 후 해당 글로 돌아온다. 공유 버튼을 누르면 하단 시트에서 링크 복사 / 다른 앱에 공유를 선택한다. HTTPS에서는 Clipboard API, 로컬 HTTP에서는 화면 밖 임시 선택 요소와 사용자 클릭 기반 복사를 사용하며 주소 입력칸은 표시하지 않는다.
- 9장 사진·투표 작성부터 전체 페이지·작성자·공감·투표 변경·댓글·동네 알리기 취소·공유 URL·다시 접속했을 때 유지되는 상태를 해당 화면 브라우저 검사로 확인했다. SQL 검사는 국가·다른 가족의 아이 사칭 방지·중복 투표·공감·댓글·지역 노출 및 사진 메타데이터에 한정한다. 전체 검사·운영 DB 변경·앱 배포는 하지 않는다.

## 댓글 반응·답글과 놀이터 전체 뷰 (079)

- 동네 놀이터 → 동네 이야기 → 육아 소통 순으로 표시한다. `/community` 첫 진입은 육아 소통이며 놀이터는 `/community/playground`에서 연다. 동네 이야기에도 같은 카테고리 선택·필터를 적용한다.
- 댓글·답글에 좋아요와 답글쓰기를 제공한다. 계정/댓글 고유키로 좋아요 중복을 막으며 재선택해 취소한다. 답글에 대한 답글도 원댓글 아래 한 단계로 묶어 모바일에서 과도하게 들여쓰지 않는다. 원댓글과 각 답글 묶음은 별도로 30개씩 커서 조회한다.
- `parenting_comment_likes`와 답글은 직접 조회·수정 권한을 주지 않고 글 국가 열람 권한과 실제 가족/아이 접근권한을 검사하는 RPC로만 다룬다. 원댓글 삭제 시 답글과 좋아요도 함께 삭제한다.
- 놀이터 전용 스타일 `playground.css`는 화면 컴포넌트와 함께 불러온다. 테두리·곡선·카드 여백을 제거하고 상단 탭과 하단 메뉴 사이의 뷰포트를 채운다. 출석·동네·우리 아이 찾기·상태 입력은 공간 위에 겹쳐 배치한다. 별도 게임 엔진이나 실시간 통신을 추가하지 않는다.
- 관련 SQL과 해당 화면 모바일/PC 브라우저 동작만 확인했다. 079는 로컬 및 개발 DB에 반영하며 전체 검사·앱 배포는 진행하지 않는다.

## 글 작성 범위·본인 글 관리 (080)

- 동네 이야기에서 작성하면 `audience=neighborhood`, 육아 소통에서 작성하면 `audience=country`로 저장한다. 동네 글은 같은 국가·시·구·동의 목록·상세·댓글·사진에서만 열리고, 국가 목록·주간 주제 집계에서 제외된다. 국가 글은 국가 목록에서 보이며 ‘동네에 알리기’를 누른 경우에만 해당 동네에도 노출된다. 동네 글에는 동네에 알리기 버튼을 두지 않는다.
- 가족 이름 + 가족관계로 글·댓글·답글 작성자를 표시한다. 아이 이름은 작성자 텍스트에서 제외한다.
- 본인 글의 목록과 상세 `…` 메뉴에서 편집·삭제한다. 편집 화면은 글쓰기 UI를 공유하며 기존 사진을 유지·제거하고 새 사진을 추가할 수 있다. 원래 게시 범위를 유지하고, 투표 참여자가 있으면 질문·선택지·투표 삭제는 제한한다. DB의 작성자 검사와 투표 잠금으로 우회·동시 수정을 제한한다.
- 사진 제거 시 제거된 파일만 정리 큐에 넣는다. 유지 사진의 메타데이터는 재생성하지 않아 정리 큐에 잘못 들어가지 않는다. 삭제 시 첨부·댓글·답글·좋아요·투표·동네 알림 데이터는 함께 제거된다.
- 카테고리 표기는 수유·분유, 건강·증상이며 저장 ID는 유지한다. 관련 권한 SQL 및 모바일 작성·편집·사진 변경·삭제·자동 복사 동작만 확인하고 전체 검사와 앱 배포는 진행하지 않는다.

## 모바일 밀도·첨부 중복 방지·공유

- 목록은 작성자 이름을 빼고 제목 한 줄·본문 최대 두 줄·작은 썸네일·지역/시각을 일정한 높이(모바일 146px, PC 154px)에 배치한다. 모바일 상단 탭과 카테고리 사이 간격은 6px로 줄인다.
- 게시글 공유는 하단 시트의 링크 복사 / 다른 앱에 공유다. 주소 입력창은 제공하지 않는다. Web Share를 지원하지 않는 환경에서는 복사 후 다른 앱에 붙여넣기를 안내한다.
- 놀이터 말풍선은 글자 길이에 맞는 폭과 최대 폭을 함께 사용한다. 우리 아이 배지를 제거하고, 일수 364까지는 D+일수, 365일부터는 연도 기준 나이를 표시한다.
- 반복 선택된 파일은 기기에서 정규화한 바이트를 비교해 중복 첨부하지 않는다. 서버에서도 표시용 WebP SHA-256을 비교해 중복 파일을 저장하지 않는다. 편집 시 유지 사진과 새 사진도 함께 검사한다. 첨부 ID·파일 경로만 비교하는 방식에 의존하지 않는다.
- 실제 개발 게시글 최근 자료는 첨부 3개·서로 다른 이미지 3개로 확인되어 임의로 지우지 않았다. 합성 자료로 3장 반복 선택 및 7개 multipart 파일 전송을 재현해 DB/상세/목록 모두 3장으로 유지되는 것을 확인했다. 원본 이미지·내용·작성자 정보는 진단 출력이나 파일로 남기지 않는다.

### 조회·인기·공유 (2026-11-03)

하단 메뉴 진입은 동네 놀이터가 기본이다. 게시글 목록과 상세에 조회수를 표시하며, 실제 상세를 연 계정당 UTC 날짜별 1회만 집계한다. 첫 카테고리는 전체/인기 선택이며 인기는 최근 7일 글을 공감×4 + 서로 다른 댓글 작성자×3 + 조회수 순으로 보여준다. 동점은 최신순이며 점수·시각·ID 커서로 다음 목록을 조회한다. 글 작성자 아이콘은 보호자 이름 첫 글자만 공개한다.

공유는 링크 복사와 지원 환경의 다른 앱 공유로 나눈다. Web Share는 HTTPS와 브라우저 지원이 필요하다. HTTP 복사는 열린 모달 내부에서 copy 이벤트로 실제 내용을 전달하며, 실패를 성공으로 표시하지 않는다. 성장일기 복사도 같은 유틸리티를 사용한다.

### 전국 소통과 검색 (2026-11-03)

상단 탭은 동네 놀이터 → 동네 이야기 → 전국 소통 순서다. 전국 소통은 한국 사용자에게 전국, 해외 사용자에게 해당 거주 국가 전체 범위로 제공한다. 전국 소통과 동네 이야기에서 제목·본문을 최대 80자 검색어로 검색한다. 검색어는 카테고리·전체/인기·추가 페이지 이동 시 유지하며 검색 변경·초기화 시 커서를 초기화한다. `%`, `_`, 역슬래시는 검색 와일드카드가 아닌 문자 그대로 처리한다. `pg_trgm` GIN 인덱스를 추가했고 국가·동네 권한 조건을 검색 전후 동일하게 유지한다.
