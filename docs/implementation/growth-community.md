# 성장일기 커뮤니티

갱신일: 2026-10-29

## 화면과 공개 범위

하단 커뮤니티는 `/[locale]/community/diaries`로 연결한다. 기존 지역·주제별 부모 게시판은 `/[locale]/community`에 유지하며 커뮤니티의 ‘부모 게시판’으로 이동한다.

| 탭                | 조회 대상                                                               | 표시 정보                                                                |
| ----------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 출생일별 성장일기 | 선택한 아이와 출생 **연·월·일**이 동일하며 해당 범위 공개를 선택한 기록 | 아이 닉네임·성별 아이콘, 몸무게(kg)·키(cm)·머리둘레(cm) 아이콘, 글, 사진 |
| 전체 성장일기     | 전체 공개를 선택한 기록                                                 | 성별, 기록 당시 D+일수, 글, 사진                                         |

D+는 기록 시간대의 날짜에서 출생일을 뺀 값이다. 출생 당일은 D+0이며, 기록 이후 시간이 흘러도 바뀌지 않는다. 신체 수치는 해당 성장 기록에 입력된 값만 사용하며 미입력값은 `—`로 표시한다. 전체 피드 RPC는 신체 수치를 null로 반환한다. 아이 닉네임은 `children.name`을 사용한다. 가족 정보와 출생일 원본은 피드에 포함하지 않는다.

## 작성과 공개 설정

‘일기 쓰기’는 기존 성장·발달 기록 작성으로 연결한다. 제목 입력 없이 본문과 사진을 남긴다. 기존 제목 값은 화면과 피드에 표시하지 않는다. 기록 상세에서 사진을 추가하고 ‘성장일기 공개’의 출생일별/전체 범위를 각각 선택한다. 둘 다 선택하거나 모두 해제할 수 있다. 성별은 선택 항목이며 아이 정보에 저장한다.

기존 기록과 새 기록은 기본 가족 전용이다. 공개 설정 저장은 해당 아이의 편집 권한이 있는 가족만 가능하다. 출생일이 없거나 출생 전/미래의 기록은 공개할 수 없다. 공개된 기록의 글·사진 수정도 공개 내용에 반영된다.

## 데이터와 접근 제어

마이그레이션 `202610260023_growth_community.sql`:

- `children.sex`: 선택적 성별.
- `growth_diary_shares`: 성장 기록별 독립적인 두 공개 설정. 원본 기록 삭제 시 함께 삭제.
- `share_growth_diary`: 권한 검사, 공개 설정 저장, 감사 로그 기록.
- `growth_diary_feed`: 로그인·동의·활성 계정 및 선택 아이 권한 검사, 탭별 필드 제한, 20개 단위 페이지.
- 원본 `children`, `child_records`, `child_record_photos`의 가족 전용 RLS는 유지.
- `/api/community/diary-photos/[id]`와 Storage 정책은 동일한 공개 권한 검사. 사진은 private/no-store 응답이며 공개 해제 후 새 요청은 차단. 커뮤니티 권한은 인증 다운로드에만 적용하고 장기 서명 URL 발급에는 적용하지 않는다.
- 기존 커뮤니티 차단 관계와 공개한 계정의 삭제 요청을 피드/사진 접근에 반영.

## 생후 일수 이동과 간결한 카드

마이그레이션 `202610260024_diary_age_navigation.sql`은 제목 없는 발달 일기를 허용하고, 피드에 닉네임과 선택적 `p_age` 필터를 추가한다. 제목·작성일은 피드에서 제외한다.

출생일별 탭 상단의 D+는 선택 아이의 현재 생후 일수로 시작한다. 화살표 또는 상단 좌우 스와이프로 D+0부터 현재 일수까지 이동하며, DB가 페이지 분할 전에 해당 일수의 기록만 조회한다. 일수 변경 시 페이지는 초기화하고, 탭·언어 변경 시 선택 일수를 유지한다. 출생일별 카드에는 D+를 중복 표시하지 않으며 전체 탭 카드에는 기록 당시 D+를 표시한다.

아이 닉네임 오른쪽에 성별 아이콘을 표시한다. 성별과 신체 수치 아이콘에는 접근성 이름·툴팁을 제공한다. 공개 설정 안내에도 닉네임이 공개됨을 명시한다.

## 성장 일기 메뉴와 우리 아이 탭

하단·PC 메뉴 이름은 **성장 일기**이며 책 아이콘을 사용한다. 기존 부모 게시판의 이름과 경로는 유지한다.

탭 순서는 **우리 아이 성장일기 → 출생일별 성장일기 → 전체 성장일기**이다. 기본 진입은 `scope=mine`이며, 우리 아이 탭은 선택한 아이의 성장 기록과 사진을 기존 가족 전용 RLS로 조회한다. 공개 여부와 무관하게 가족에게 허용된 기록을 보여주며, 공개용 피드나 사진 API를 사용하지 않는다. `일기 관리`에서 기록 상세·수정·공개 설정으로 이동한다. 조회 전용 가족에게는 `일기 보기`로 표시한다.

## 성장 데이터와 신고

출생일별 카드 오른쪽 더보기 메뉴에 **성장 데이터 보기**와 **신고하기**를 제공한다. 상단 D+는 기본적으로 선택 아이의 현재 생후 일수이며 좌우 버튼·스와이프로 변경한다.

성장 데이터는 해당 아이가 같은 출생일 그룹에 공개한 측정 기록을 D+ 오름차순으로 보여준다. 키(cm)·몸무게(kg)·머리둘레(cm)를 표시하며 미입력 값은 `—`이다. 비공개·전체 탭에만 공개된 기록·운영자 숨김 기록은 포함하지 않는다. 100개씩 더 보기로 모든 기록을 조회할 수 있다. 모바일에서는 하단 시트, PC에서는 대화상자로 표시한다.

마이그레이션 `202610260025_diary_history_reports.sql`은 생후 일수별 공개 이력 조회와 신고 저장을 추가한다. 신고는 기존 `community_reports`에 연결하며 미처리 상태의 같은 사용자·일기 신고는 한 건만 저장한다. 운영 검토를 위해 신고 당시 공개된 닉네임·본문을 저장하고, 원본 기록 삭제 시 신고도 함께 삭제된다. 운영 관리에서 사유와 신고 본문 확인, 숨김·숨김 해제·처리 완료가 가능하다. 숨긴 일기는 공개 목록·성장 이력·사진 접근에서 제외하되 가족 전용 원본은 유지한다.

## 우리 아이 일기 작성

- 성장 일기 상단에는 부모 게시판·일기 쓰기 버튼을 표시하지 않습니다.
- 우리 아이 성장일기 목록 아래의 펜 아이콘으로 하단 작성 화면을 엽니다. 가족의 기록 작성 권한이 있는 사용자에게만 표시합니다.
- 제목과 기록 종류 선택 없이 글, 사진, 선택 항목인 몸무게(kg)·키(cm)·머리둘레(cm)를 저장합니다. 글·사진·수치 중 하나는 입력해야 합니다.
- 성장 수치가 있으면 기존 `measurement`, 없으면 `observation`으로 저장하므로 성장 통계와 기존 DB 제약을 유지합니다. 공개 설정은 기존 일기 관리 화면에서 변경합니다.
- 작성 시 사진 1장(최대 5MB, PNG/JPEG/WebP)을 첨부할 수 있고, 일기 관리에서 추가 관리합니다. 사진 업로드만 실패하면 일기 저장 사실과 재첨부 방법을 안내합니다.

### 목록과 관리 화면

우리 아이 일기 카드에는 이름·성별을 반복하지 않고, 상단 더보기 아이콘 옆에 편집·삭제 메뉴를 엽니다. 탭과 목록 사이에 간격을 둡니다. 메뉴는 바깥 클릭이나 Escape로 닫히며, 편집을 선택하면 하단 작성 화면을 엽니다. 편집은 기록 날짜, 기존 사진, 공개 설정을 유지합니다. 삭제는 확인 후 기존 권한 검사와 사진 정리 절차를 사용합니다.

## 하루 패턴 이미지 첨부 (2026-10-28)

일기 작성·편집 화면의 `하루 패턴 올리기`에서 날짜를 선택하면 해당 아이의 실제 돌봄 기록을 24시간 원형 패턴 PNG로 생성한다. 저장 전에 미리보기와 제거를 지원하며, 일반 사진과 합쳐 최대 9장까지 첨부한다. 이미지에는 선택 날짜와 하단 한 줄의 기능별 색상 범례를 포함한다. 원 그래프는 이미지의 가로 중앙에 두고, 개별 시각·기능 목록 대신 하단에 하루 총 먹은 양(ml), 배변 횟수, 총 수면 시간을 한 줄로 표시한다. 원 가운데에는 현재 언어로 24시간을 표시한다. 먹은 양은 입력된 ml만 합산하고 수면은 완료된 기록을 해당 날짜 경계로 나눠 중복 구간을 제거해 합산한다. 업로드 패턴은 기능 선택 필터 없이 모든 시간 기록을 포함한다. 배변(dirty·mixed)은 오늘 목록과 동일하게 배변 패턴으로만 표시하고 기저귀 패턴에 중복 표시하지 않는다. 별도로 등록된 기저귀 기록(wet)은 같은 시각이어도 유지한다. 통계용 기저귀 교체 횟수 집계는 유지한다.

서버에서 가족 쓰기 권한과 아이·날짜를 확인한다. 생성 이미지는 기존 일기 사진 저장 경로를 사용하고 일기의 공개·비공개 설정을 따른다. 저장한 이미지는 첨부 시점의 기록이며 이후 돌봄 기록 변경에 따라 자동 갱신되지 않는다.

### 사진 미리보기와 순서 (2026-10-28)

사진과 하루 패턴을 합쳐 최대 9장까지 첨부한다. 사진 선택을 여러 번 하면 기존 선택에 추가하며, 새 첨부와 기존 사진 모두 미리보기의 × 버튼으로 제거할 수 있다. 취소하면 기존 사진은 유지되며, 저장할 때 `save_growth_diary`가 버전·사진 소속을 확인하고 일기 변경과 사진 제거를 같은 트랜잭션으로 처리한다. 제거된 파일은 기존 Storage 정리 큐에 등록된다. 미리보기의 좌우 화살표로 기존 사진과 새 사진·패턴의 순서를 함께 변경한다. `child_record_photos.sort_order`와 권한 검증 RPC `reorder_diary_photos`로 순서를 저장하고, 내 일기·공개 피드·공유 페이지 모두 같은 순서를 사용한다. 장당 5MB 제한은 유지한다.

성장일기 상세 화면은 둥근 모서리의 사진 아래에 별도 글 영역을 배치한다. 사진 선택 표시는 사진 아래에 두고, 사진과 본문을 겹치지 않도록 유지한다.

사진 스와이프 중에는 현재 사진 영역 높이를 유지한다. 손가락을 떼고 관성 스크롤이 끝난 뒤 새 사진의 높이를 반영하며, 상세·공유 페이지에서 같은 처리를 사용한다.

하루 패턴 이미지는 세로 사진과 같은 3:4 비율(1800×2400)로 생성한다. 별도 제목 없이 현재 UI 언어로 날짜·시간·요약 수치·범례를 표시하며 요약 수치 배경 카드는 사용하지 않는다. 저장 후 목록 위에 업로드 결과 안내 문구를 삽입하지 않는다.

오늘 메뉴 기능 목록의 첫 항목은 성장 기록이며, 기존 일기 작성 화면으로 연결한다. 오늘 타임라인의 성장 측정·관찰·일기 항목은 성장 기록으로 통일해 표시한다. 인사이트 기능 목록은 이 추가 버튼의 영향을 받지 않는다.

### 보호자 관계와 일기 작성자 (2026-10-28)

- 첫 가족 등록과 초대 수락 시 아이와의 관계를 필수 선택합니다. 가족별 보호자 관계는 접근 권한(owner/editor/viewer)과 별도로 저장합니다. 계정 설정에서 본인의 관계를 변경할 수 있습니다.
- 마이그레이션 045는 사용자 요청에 따라 기존 보호자를 아빠로 채우며, 원작성자가 남아 있는 기존 일기도 아빠 작성으로 채웁니다. 작성자가 이미 삭제된 일기는 보호자로 표시합니다.
- 성장일기에는 작성 당시의 관계를 저장합니다. 다른 보호자가 편집하거나 이후 관계를 변경해도 원작성자 표시는 유지됩니다. 내 일기·출생일별·전체 목록 및 공유 링크에서는 작성자 관계를 표시하지 않습니다. 상세 화면 맨 아래에만 `by 아빠` 형식으로 표시합니다. 관계 데이터는 DB에 그대로 보관합니다.
- 기존 관계 없는 RPC 호출은 허용하지 않습니다. 내부 호환 함수는 인증 사용자에게 실행 권한을 부여하지 않습니다.

### 사진 표시용 파일 사전 생성 (2026-10-28)

업로드한 원본은 비공개 `child-care-photos`에 유지하고, 같은 경로에 `.display-v1-480.webp`, `.display-v1-1600.webp`를 붙인 표시용 파일을 저장합니다. 긴 변 기준 480px(품질 76), 1600px(품질 90), 작은 사진은 확대하지 않습니다. 최대 9장의 디코딩은 순차 처리하여 메모리 사용을 제한합니다. 두 파일의 저장을 DB에서 확인한 뒤 `variants_ready`를 켭니다. 변환 실패 시 업로드된 원본을 유지하고 기존 경로로 표시합니다.

목록·상세·공유 사진 API는 매 요청 권한 확인 후 준비된 파일을 바로 전달합니다. 브라우저 조건부 요청도 권한 확인 이후에 처리합니다. 기존 사진 또는 저장 파일 누락 시에만 원본 변환으로 호환합니다. 사진 삭제 큐에는 원본과 두 변환본 모두 들어가며, 정상 연결된 변환본은 미등록 파일 정리에서 제외합니다.

기존 사진은 `node --env-file=.env.local scripts/backfill-diary-photo-variants.mjs --expected-url=<정확한 프로젝트 URL> --dry-run`으로 건수를 먼저 확인하고, `--dry-run`을 빼서 생성합니다. 서버 전용 키가 필요하며 경로·키·사용자 데이터는 출력하지 않습니다. 실패 건은 원본을 유지하며 스크립트 재실행으로 재시도할 수 있습니다.

마이그레이션 046에 일기별 사진 순서 인덱스 및 공개 목록 시간순 인덱스를 추가했습니다. 로컬 트랜잭션에서 일기 1,000개·사진 메타데이터 9,000개로 권한 검사를 포함한 21행 조회를 측정했습니다. 내 일기의 동등한 SQL은 약 8–15ms, 전체 공개 feed RPC는 약 177–186ms였습니다. 네트워크와 실제 운영 데이터 분포는 포함하지 않으며, 이 수치를 운영 성능 보장이나 인덱스 개선율로 해석하지 않습니다.

### 메뉴 재방문 미리보기 (2026-10-28)

사진 API의 `private, no-cache`는 파일 재전송 없이 304를 반환해도 권한 확인 왕복이 필요합니다. 메뉴 재방문에서 미리보기만 늦게 보이는 문제를 줄이기 위해, 처음 권한 확인을 거쳐 표시한 480px 사진을 동일 로그인 세션의 브라우저 메모리에 보관합니다. 사용자 ID와 최근 로그인 시각으로 범위를 구분하며, 최대 5분·80장·인코딩 문자열 24MiB로 제한합니다. 계정/로그인 세션 변경 시 캐시는 비우며 이전 세션의 늦은 응답은 저장하지 않습니다. localStorage나 공개 HTTP 캐시는 사용하지 않습니다.

첫 화면은 일반 이미지 URL로 서버 렌더링하여 초기 로드를 늦추지 않습니다. 로드가 완료되면 브라우저에 이미 저장된 응답을 재사용해 미리보기를 준비하고, 이후 클라이언트 메뉴 전환에서는 메모리의 이미지를 사용합니다. 서버에서 허용한 일기 목록에 포함된 사진만 렌더링하며 상세·공유 사진 API 권한 정책은 유지합니다. 삭제·권한 회수는 새 목록/API 조회에서 반영되며 이미 내려받아 표시 중인 이미지를 원격으로 회수하는 기능은 아닙니다.

검증: 모바일 메뉴 왕복 시 해당 사진 네트워크 요청 0건, 사진 삭제 후 조건부 API 요청 404, 세션 분리·만료·최대 보관 건수 테스트 통과.

### 하루 패턴·하루 기록 이미지 첨부 (2026-10-29)

일기 작성·편집의 사진 추가 옆에 `하루 패턴`, `하루 기록`을 둡니다. 날짜를 선택하면 해당 아이의 기록만 읽어 이미지로 첨부합니다. 하루 패턴은 1800×2400이며, 하루 기록은 폭 1800px에 실제 기록 수에 맞는 높이로 생성합니다. 두 이미지 모두 기존 사진과 함께 미리보기·순서 변경·제거할 수 있으며 일기당 최대 9장에 포함합니다.

하루 패턴 중앙에는 선택 날짜의 `D+일수`를 표시합니다. 하루 기록 이미지는 오늘 타임라인과 같은 기록을 시간순(최신 먼저)으로 나열하고, 시간·항목·양·소요시간·측정값을 표시합니다. 성장일기의 본문이나 다른 사진을 다시 이미지에 복제하지 않습니다. 기록이 많은 날은 이미지당 18개씩 나누며 첨부 여유 공간이 부족하면 일부 기록을 버리는 대신 첨부하지 않습니다. 날짜·항목·수치는 사용 중인 한국어/영어 설정으로 생성합니다.

권한과 날짜는 서버에서 다시 검증합니다. 가족의 편집 권한이 필요하고 출생 전·미래 날짜는 첨부할 수 없습니다. 과거 날짜에 아직 끝나지 않은 기록과 미래 시각의 기록은 하루 기록 이미지에 넣지 않습니다.
