# 성장일기 커뮤니티

갱신일: 2026-10-26

## 화면과 공개 범위

하단 커뮤니티는 `/[locale]/community/diaries`로 연결한다. 기존 지역·주제별 부모 게시판은 `/[locale]/community`에 유지하며 커뮤니티의 ‘부모 게시판’으로 이동한다.

| 탭                | 조회 대상                                                               | 표시 정보                                                                |
| ----------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 출생일별 성장일기 | 선택한 아이와 출생 **연·월·일**이 동일하며 해당 범위 공개를 선택한 기록 | 아이 닉네임·성별 아이콘, 몸무게(kg)·키(cm)·머리둘레(cm) 아이콘, 글, 사진 |
| 전체 성장일기     | 전체 공개를 선택한 기록                                                 | 성별, 기록 당시 D+일수, 글, 사진                                         |

D+는 기록 시간대의 날짜에서 출생일을 뺀 값이다. 출생 당일은 D+0이며, 기록 이후 시간이 흘러도 바뀌지 않는다. 신체 수치는 해당 성장 기록에 입력된 값만 사용하며 미입력값은 `—`로 표시한다. 전체 피드 RPC는 신체 수치를 null로 반환한다. 아이 닉네임은 `children.name`을 사용한다. 가족 정보와 출생일 원본은 피드에 포함하지 않는다.

## 작성과 공개 설정

‘일기 쓰기’는 기존 성장·발달 기록 작성으로 연결한다. 제목 입력 없이 본문과 사진을 남긴다. 기존 제목 값은 화면과 피드에 표시하지 않는다. 기록 상세에서 사진을 추가하고 ‘성장일기 공개’의 출생일별/전체 범위를 각각 선택한다. 둘 다 선택하거나 모두 해제할 수 있다. 성별은 선택 항목이며 아이 정보에 저장한다.

기존 기록과 새 기록은 기본 가족 전용이다. 공개 설정 저장은 해당 아이의 편집 권한이 있는 가족만 가능하다. 출생일이 없거나 출생 전/미래의 기록은 공개할 수 없다. 공개된 기록의 글·사진 수정도 공개 내용에 반영된다.

## 데이터와 접근 제어

마이그레이션 `202610260023_growth_community.sql`:

- `children.sex`: 선택적 성별.
- `growth_diary_shares`: 성장 기록별 독립적인 두 공개 설정. 원본 기록 삭제 시 함께 삭제.
- `share_growth_diary`: 권한 검사, 공개 설정 저장, 감사 로그 기록.
- `growth_diary_feed`: 로그인·동의·활성 계정 및 선택 아이 권한 검사, 탭별 필드 제한, 20개 단위 페이지.
- 원본 `children`, `child_records`, `child_record_photos`의 가족 전용 RLS는 유지.
- `/api/community/diary-photos/[id]`와 Storage 정책은 동일한 공개 권한 검사. 사진은 private/no-store 응답이며 공개 해제 후 새 요청은 차단. 커뮤니티 권한은 인증 다운로드에만 적용하고 장기 서명 URL 발급에는 적용하지 않는다.
- 기존 커뮤니티 차단 관계와 공개한 계정의 삭제 요청을 피드/사진 접근에 반영.

## 검증

`npx supabase test db supabase/tests/growth_community.test.sql`은 비공개 기본값, 정확한 출생일 일치, 공개 범위별 수치 제한, D+ 시간대, 다른 가족 권한, 공개 해제와 사진 접근을 검사한다.

`npm run test:local -- --grep 'growth community'`는 두 가족의 실제 브라우저 세션으로 게시/조회/공개 해제, 사진 API, 한·영 전환, PC·모바일 표시를 검증한다.

## 화면 확인용 예시

사용자 요청으로 `scripts/fixtures/growth-community-examples.sql`의 가상 일기 4개를 연결된 DB에 추가했다. 출생일별 3개, 전체 4개이며 아이 닉네임의 `[예시]`와 본문의 가상 자료 안내로 구분한다. 별도 가상 가족과 로그인 차단 계정을 사용하고 실제 가족 기록을 변경하지 않는다. 사진 없는 일기와 측정값 입력/미입력 상태를 보여준다.

이 SQL은 자동 마이그레이션이나 자동 시드에 포함하지 않는다. 고정 ID로 재실행 시 중복 생성하지 않으며, 예시 가족 ID `d17a0000-47f0-4abc-8abd-000000000002`와 예시 사용자 ID `d17a0000-47f0-4abc-8abd-000000000001`로 실제 자료와 구분한다.

## 생후 일수 이동과 간결한 카드

마이그레이션 `202610260024_diary_age_navigation.sql`은 제목 없는 발달 일기를 허용하고, 피드에 닉네임과 선택적 `p_age` 필터를 추가한다. 제목·작성일은 피드에서 제외한다.

출생일별 탭 상단의 D+는 선택 아이의 현재 생후 일수로 시작한다. 화살표 또는 상단 좌우 스와이프로 D+0부터 현재 일수까지 이동하며, DB가 페이지 분할 전에 해당 일수의 기록만 조회한다. 일수 변경 시 페이지는 초기화하고, 탭·언어 변경 시 선택 일수를 유지한다. 출생일별 카드에는 D+를 중복 표시하지 않으며 전체 탭 카드에는 기록 당시 D+를 표시한다.

아이 닉네임 오른쪽에 성별 아이콘을 표시한다. 성별과 신체 수치 아이콘에는 접근성 이름·툴팁을 제공한다. 공개 설정 안내에도 닉네임이 공개됨을 명시한다.

## 성장 일기 메뉴와 우리 아이 탭

하단·PC 메뉴 이름은 **성장 일기**이며 책 아이콘을 사용한다. 기존 부모 게시판의 이름과 경로는 유지한다.

탭 순서는 **우리 아이 성장일기 → 출생일별 성장일기 → 전체 성장일기**이다. 기본 진입은 `scope=mine`이며, 우리 아이 탭은 선택한 아이의 성장 기록과 사진을 기존 가족 전용 RLS로 조회한다. 공개 여부와 무관하게 가족에게 허용된 기록을 보여주며, 공개용 피드나 사진 API를 사용하지 않는다. `일기 관리`에서 기록 상세·수정·공개 설정으로 이동한다. 조회 전용 가족에게는 `일기 보기`로 표시한다.

## 성장 데이터와 신고

출생일별 카드 오른쪽 더보기 메뉴에 **성장 데이터 보기**와 **신고하기**를 제공한다. 상단 D+는 기본적으로 선택 아이의 현재 생후 일수이며 좌우 버튼·스와이프로 변경한다.

성장 데이터는 해당 아이가 같은 출생일 그룹에 공개한 측정 기록을 D+ 오름차순으로 보여준다. 키(cm)·몸무게(kg)·머리둘레(cm)를 표시하며 미입력 값은 `—`이다. 비공개·전체 탭에만 공개된 기록·운영자 숨김 기록은 포함하지 않는다. 100개씩 더 보기로 모든 기록을 조회할 수 있다. 모바일에서는 하단 시트, PC에서는 대화상자로 표시한다.

마이그레이션 `202610260025_diary_history_reports.sql`은 생후 일수별 공개 이력 조회와 신고 저장을 추가한다. 신고는 기존 `community_reports`에 연결하며 미처리 상태의 같은 사용자·일기 신고는 한 건만 저장한다. 운영 검토를 위해 신고 당시 공개된 닉네임·본문을 저장하고, 원본 기록 삭제 시 신고도 함께 삭제된다. 운영 관리에서 사유와 신고 본문 확인, 숨김·숨김 해제·처리 완료가 가능하다. 숨긴 일기는 공개 목록·성장 이력·사진 접근에서 제외하되 가족 전용 원본은 유지한다.

## 우리 아이 일기 작성

- 성장 일기 상단에는 부모 게시판·일기 쓰기 버튼을 표시하지 않습니다.
- 우리 아이 성장일기 목록 아래의 펜 아이콘으로 하단 작성 화면을 엽니다. 가족의 기록 작성 권한이 있는 사용자에게만 표시합니다.
- 제목과 기록 종류 선택 없이 글, 사진, 선택 항목인 몸무게(kg)·키(cm)·머리둘레(cm)를 저장합니다. 글·사진·수치 중 하나는 입력해야 합니다.
- 성장 수치가 있으면 기존 `measurement`, 없으면 `observation`으로 저장하므로 성장 통계와 기존 DB 제약을 유지합니다. 공개 설정은 기존 일기 관리 화면에서 변경합니다.
- 작성 시 사진 1장(최대 5MB, PNG/JPEG/WebP)을 첨부할 수 있고, 일기 관리에서 추가 관리합니다. 사진 업로드만 실패하면 일기 저장 사실과 재첨부 방법을 안내합니다.

### 목록과 관리 화면

우리 아이 일기 카드에는 이름·성별을 반복하지 않고, 상단 더보기 아이콘으로 관리 하단 화면을 엽니다. 탭과 목록 사이에 간격을 둡니다. 관리 화면은 내용·성장 수치·사진과 편집/삭제 버튼을 표시합니다. 편집은 같은 하단 화면에서 수행하며 기록 날짜, 기존 사진, 공개 설정을 유지합니다. 삭제는 확인 후 기존 권한 검사와 사진 정리 절차를 사용합니다.
