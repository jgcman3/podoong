# 현재 데이터 형식 원칙

수정: 2026-11-02

- 출시 전 서비스이므로 구형 데이터 형식의 조회·편집·변환 분기와 구형 API를 유지하지 않는다. 현재 형식으로 정상 동작하는 기록은 삭제하지 않는다.
- 먹이기 양은 ml만 사용한다. 사용하지 않는 g 필드·구형 돌봄/일정 저장 API와 관리자 추가 인증의 이전 경로를 제거했다. g 자료는 ml로 변환하지 않는다.
- 없는 테이블이나 예전 스키마에 대체 조회하는 분기를 제거했다. 현재 스키마가 없으면 오류로 처리한다.
- 시간대 미상 값, 사용자가 직접 입력한 소요시간, 사진 파생본 생성 실패 시 원본 사용은 현재도 유효한 동작이다. 구형 호환으로 취급해 삭제하지 않는다.
- 과거 정리 마이그레이션을 다시 실행하는 전용 검증 스크립트·픽스처는 제거했다. 현재 API의 권한·재전송 중복 방지·수정 충돌·날짜·단위 동작을 검증한다. 과거부터 현재까지의 정상 기록 조회는 유지한다.
- 로컬 g 자료 0건, 개발·운영 Supabase g 자료 각각 0건으로 확인했다. 이후 사용자 승인으로 개발 Supabase에 070~076 스키마를 적용했다. 운영 DB와 새 앱 배포는 수행하지 않았다. 지원금 전용 키·수집 함수·예약은 개발 Supabase에서 정리했다.
- 로컬 스키마 정리 전 전체 DB 백업을 Git 제외 `.secrets/backups/`에 소유자 전용으로 보관하고 아카이브 형식을 검증했다. 시간대 누락을 삭제 조건에 포함하지 않는다.
- 확인한 대상은 현재 실행 소스·테스트·구형 API다. DB를 새로 구성하는 스키마 이력은 유지하며 전체 서비스 검사·개발 배포는 별도 요청 전까지 보류한다.
