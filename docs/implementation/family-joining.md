# 가족 시작과 기존 가족 참여

작성일: 2026-10-30

## 가입 흐름

소셜 로그인과 필수 약관 동의를 마친 뒤 ‘처음 시작해요’와 ‘가족이 이미 사용 중이에요’를 선택한다. 처음 시작할 때만 가족 이름 → 보호자 이름 → 아이 이름 → 아이 성별 → 아이 태어난 날 → 아이와 나의 관계 순서로 필수 정보를 입력한다. 시간대도 필수이며 기기의 시간대를 자동 선택한다. UTC와 서버 런타임이 제공하는 전 세계 IANA 시간대를 지역별로 표시한다. 저장된 선호 시간대가 있으면 유지하고, 자동 감지가 준비되지 않은 경우 서울을 기본으로 사용한다. 서버와 DB도 기존 5개 제한 대신 유효한 IANA 이름을 검증한다.

640px 미만의 모바일 화면은 한 항목씩 입력하고 ‘다음/이전’으로 이동한다. PC는 전체 입력을 한 페이지에 표시한다. 같은 입력 요소를 유지하므로 이전 이동이나 창 크기 변경으로 값이 사라지지 않는다. 모바일은 현재 항목을 확인한 뒤 진행하며, 마지막 제출에서 전체 필수값을 다시 검증한다. 중간 단계에는 DB를 저장하지 않는다. 스크립트가 준비되지 않은 경우에도 전체 폼과 브라우저의 필수값 검증으로 가입할 수 있다.

단계 이동은 클릭/키 입력 처리 안에서 표시 상태를 반영한 뒤 다음 입력에 즉시 포커스를 준다. iOS의 사용자 동작 범위를 벗어나지 않도록 포커스를 애니메이션 프레임까지 미루지 않는다. 입력·진행 표시·버튼 스타일은 폼 전용 CSS 모듈로 함께 로드한다.

기존 가족은 초대 링크 또는 원문 코드를 입력해 참여한다. 초대 링크로 들어왔다면 가족 선택을 생략하고 본인 이름과 관계만 입력한다. 아이 이름·생일·소셜 계정 정보로 같은 가족을 추정하거나 자동 연결하지 않는다. 이미 접근 가능한 아이가 있다면 DB도 새 가족을 중복 생성하지 않는다.

## 각자 가족을 만든 경우

아이 이름 메뉴의 ‘기존 가족에 참여하기’에서 초대를 확인한다. 참여 전 목적지 가족, 가져갈 아이 목록, 접근 권한과 보존 정책을 표시한다.

- 혼자 관리하던 가족의 모든 아이를 목적지 가족으로 옮긴다. 아이 ID와 돌봄·일기·사진·일정·공유 링크는 유지한다.
- 이름·성별·생일이 같아도 아이 항목이나 기록을 자동 합치거나 삭제하지 않는다. 가족관리자는 데이터 설정에서 아이별 기록을 확인한 뒤 별도로 영구 삭제할 수 있다.
- 참여한 가족의 관리자가 옮긴 아이를 관리한다. 목적지 주소 설정을 사용하며, 원래 가족의 메타데이터와 이력은 `merged_into`로 연결해 보관한다. 빈 옛 가족은 동네 신청 수에 중복 반영하지 않는다.
- 기존 가족에 다른 보호자가 남아 있으면 일방적으로 옮길 수 없다. 보기 전용 초대로 관리하던 아이를 옮기거나 편집 권한을 높일 수도 없다.
- 일반 보호자로 참여 중인 다른 가족의 아이·접근 권한은 변경하지 않는다.

## 안전성과 검증

미리보기의 가족·아이 목록과 확인 시점의 상태가 다르면 재확인을 요구한다. 최근 로그인, 관계 및 명시적 동의를 확인하고 초대 수락과 이동을 단일 DB 트랜잭션으로 처리한다. 만료·재사용·실패 시 기존 자료는 그대로 남는다. 이전 가족에서 발급한 미사용 초대는 무효화한다.

사진 경로와 ID는 변경하지 않는다. 다른 가족에 보존된 사진은 업로더 계정 삭제 시 함께 삭제하지 않으며 업로더 표시만 비운다. 실제 아이/일기 삭제 시 기존 정리 작업이 원본과 표시용 이미지를 제거한다. 본인이 관리하던 가족의 탈퇴 삭제 동작은 유지한다.

개발 중에는 변경과 관련된 단위·SQL·브라우저 시나리오만 실행한다. 전체 CI는 개발/운영 배포 경계에서 수행한다. 이번 관련 검사는 부분 동의/스크립트 지연, 모바일 입력 폭과 순서, 영문 초대, 기존 가족 합류, 중복 아이 보존, 권한·재확인·사진·탈퇴 처리다.
