# Supabase 서울 리전 이전

작성일: 2026-10-29 · 상태: 데이터·사진 이전 및 로컬 앱 전환 완료, 실제 사용자 재로그인 확인 필요

## 프로젝트와 현재 연결

| 구분 | 프로젝트               | 리전                    | 상태                                     |
| ---- | ---------------------- | ----------------------- | ---------------------------------------- |
| 기존 | `mkybqrhjrpouxmxizmpt` | 시드니 `ap-southeast-2` | 복구용으로 유지, 로컬 앱 연결 해제       |
| 신규 | `atdyjsxfxlhwxmxgtnte` | 서울 `ap-northeast-2`   | 로컬 앱·CLI 연결, 마이그레이션 51개 적용 |

기존 프로젝트를 삭제하거나 초기화하지 않았다. DB·사진 검증 후 `.env.local`과 CLI 연결을 서울로 전환하고 개발 서버를 LAN 모드로 재시작했다. 로컬 접속 주소는 `http://192.168.45.85:3187`이다. 별도 운영 배포가 있다면 그 환경 변수도 따로 전환해야 한다.

## 완료된 준비

- 기존 DB 구조와 데이터 백업 완료. 백업에는 개인정보·인증 자료가 있으므로 저장소에 넣지 않고 권한을 제한한 임시 경로에 보관한다.
- 백업 기준 계정 3개, 가족 2개, 아이 5명, 돌봄 기록 8개, 성장 기록 13개, 사진 메타데이터 9개를 확인했다. 이후 입력분은 최종 전환 전에 다시 확인한다.
- 카카오 Developers에 서울 콜백 URI를 추가했다고 운영자가 확인했다. 기존 콜백은 검증 동안 유지한다.

## 복원 작업의 범위

서울 프로젝트에만 기존 계정 식별자와 소셜 연결, 가족·아이·돌봄·성장일기·사진 메타데이터·일정·할 일·공유 링크·권한·지역 자료를 복원한다. 인증 내부 테이블의 호환성을 먼저 확인한다. 기존 로그인 세션은 새 프로젝트에서 재로그인이 필요할 수 있으며, 사용자 UUID와 소셜 식별자를 보존하여 계정 중복을 방지한다.

운영자의 명시적 승인 후 복원했다. 기존 시드니는 변경하지 않고 신규 서울 대상에만 트랜잭션으로 복원했다. 로그인 사용자·소셜 식별자는 보존하고 구 프로젝트의 임시 OAuth 상태와 세션·갱신 토큰은 이전하지 않았다. 새 프로젝트에서 재로그인해야 한다.

초기 게시판 5개의 UUID가 새로 생성된 문제는 해당 ID를 참조하는 게시글이 없음을 확인한 뒤, 정확히 5개 행에만 원본 ID를 적용해 해결했다. 외래키를 활성 상태로 유지했고 증가 ID 시퀀스도 원본에 맞췄다.

Storage 파일 47개를 동일 경로로 복사하고 각 파일의 SHA-256이 원본과 일치함을 확인했다. 버킷은 비공개를 유지했다.

## 검증 결과

- 최종 시드니 스냅샷과 서울의 앱 테이블 및 Auth 사용자·소셜 식별자 테이블, 총 51개를 컬럼과 전체 행 기준으로 비교해 차이 없음.
- 공개 스키마 외래키 76개 검증 통과. RLS 활성 테이블 49개와 정책 45개 확인.
- Auth DB 사용자 3개, 소셜 식별자 2개 보존. Auth 관리 API에서 보이는 활성 계정 2개의 ID도 원본과 일치.
- 일기 사진 메타데이터 9개 모두 표시용 이미지 준비 상태 유지. 비로그인 프로필·아이 조회와 비공개 Storage 직접 다운로드 차단 확인.
- 서울 Kakao Provider 활성화, 카카오 인증 페이지로 302 이동 및 서울 콜백 URI 확인. LAN 복귀 주소 유지.
- 모바일 크기 브라우저의 실제 로그인 버튼으로 서울 인증 URL·LAN 복귀 경로·닉네임 전용 scope 연결 확인. 로그인 화면 JavaScript 오류 없음.
- 실제 카카오 계정의 인증 완료·재로그인, 로그인 후 아이 선택·기록 저장은 사용자의 기기에서 최종 확인 필요. 타인의 소셜 계정으로 대신 로그인하지 않음.

## 남은 스키마 차이

커밋 전 DB 회귀 검사에서 발견한 회원 일기 목록 RPC의 기본 익명 실행 권한은 후속 마이그레이션 `202610290052_diary_feed_anon_permission.sql`로 제한한다. 이 후속 변경은 로컬에서 검증하며 서울·시드니 원격 DB에는 아직 적용하지 않았다. 원격 배포 시 별도로 적용해야 한다. 토큰 기반 공개 일기 링크 RPC의 권한은 변경하지 않는다.

원본에만 `public.rls_auto_enable()` 이벤트 트리거용 보조 함수가 있다. 앱 마이그레이션에 포함된 함수·테이블·정책과 달리 신규 프로젝트에 기본 생성되지 않았다. 현재 테이블 RLS 검증은 통과했지만, 이 함수 정의·권한 복원은 SECURITY DEFINER 보안 설정 변경이라는 이유로 자동 승인 검토가 거절하여 별도 승인을 요청했다. 함수와 연결된 이벤트 트리거의 실제 존재·활성 상태도 확인한 뒤 복원 여부를 판단한다. 아직 해당 보조 함수를 복원했다고 보고하지 않는다.

## 전환 조건

1. 서울 Kakao Provider와 Site URL·Redirect URLs를 기존 설정에 맞춘다. 비밀키는 채팅이나 Git에 남기지 않는다.
2. 계정·테이블별 데이터와 관계·RLS·RPC를 확인하고 사진 파일의 내용이 일치하는지 검증한다.
3. 앱 URL·공개 키·서버 키와 CLI 연결을 서울 프로젝트로 함께 변경하고 개발 서버를 재시작한다.
4. 실제 카카오 재로그인, 아이 선택, 기록 조회, 일기 사진·공유 링크와 저장 기능을 검증한다.
5. 실제 전환이 확인된 뒤 개인정보 처리방침의 주 저장 위치를 대한민국 서울로 변경한다. 지원·로그·재위탁의 해외 처리는 별도로 확인한다.

실패하면 기존 환경 설정과 시드니 연결로 되돌린다. 전환 후 서울에 새 데이터가 생겼다면 단순 복귀 전에 변경분을 보존해야 한다. 구 프로젝트와 백업의 최종 삭제는 별도 확인 후 수행한다.
