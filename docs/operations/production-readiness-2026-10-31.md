# 운영 공개 준비 점검

점검일: 2026-10-31 · 판정: 개발 검증 후 운영 공개 준비 필요

## 확인한 현재 상태

- `podoong.com`과 `dev.podoong.com` 모두 HTTPS 응답을 제공한다. 운영 주소는 이미 Vercel의 이전 Production 배포(`dpl_3yS2P1LxZTBs5HiG6zCufSWd12mp`, READY)에 연결되어 있다. **운영 주소가 전혀 열리지 않는 상태가 아니다.** 최신 기능의 운영 반영 완료와는 구분한다.
- Vercel 운영 환경을 비공개 임시 파일로 읽고 즉시 제거했다. 운영 DB는 서울 `atdyjsxfxlhwxmxgtnte`, 운영 URL은 `https://podoong.com`, 활성 로그인 목록은 `kakao`이며 서버 전용 키가 존재한다. 공개 출력에 키 값은 포함하지 않았다.
- 개발 DB는 별도 서울 `aacmsohijybjiyidfzgy`다. 개발/운영 분리는 완료됐으며 프로젝트나 도메인을 다시 구매할 필요가 없다.
- 운영 DB dry-run에서 `059`~`064` 여섯 마이그레이션이 대기 중임을 확인했다. 운영 DB를 변경하지 않았다.
- `main`의 Branch Protection 조회는 미설정이며 활성 branch Ruleset도 없다. GitHub Environments는 개발/운영 브랜치를 제한하지만 운영 reviewer 규칙은 없다. 따라서 Environment 제한만으로 main 직접 푸시가 차단되지는 않는다.
- 이번 소개·이미지 설치 안내·어제 기준 알림 변경은 작업 브랜치와 `develop`에 반영해 CI 후 개발에 배포한다. 정확한 배포 결과는 해당 커밋의 GitHub Actions 결과로 확인한다. 이번 작업에서 `main`이나 운영 DB를 갱신하지 않는다.

| 2 | 비용·이용 한도 | Vercel/Supabase 실제 플랜·사진 용량·이미지 변환/전송·함수 호출 사용량과 비용 알림을 확인한다. 이번 점검은 요금제를 변경하지 않았다. 외부 가동 점검과 장애 연락도 연결한다. |
| 2 | 예시 자료 분리 | 운영자가 확인한 개발 예시·테스트 계정만 정리한다. 운영의 기존 아이·일기·사진이나 가족 병합 자료를 자동 삭제하지 않는다. 이전용 백업의 보관 종료도 정한다. |

## 운영자가 결정할 것과 개발 작업

운영자에게 새 API 키를 일괄 요청할 상황은 아니다. 우선 결정이 필요한 것은 **초기 제공 국가 / 공개·공유 정책 / 보관기간·백업 목표 / 실제 공개일**이다. 이미 확인한 운영자 이름과 문의 이메일을 다시 입력할 필요는 없다. 서비스 전용 메일 분리는 추후 선택할 수 있다.

개발 작업은 동의·철회 연결, 예약 삭제 작업과 감시, 운영 백업/복원 검증, main 보호, 실제 단말 검증 및 최종 릴리스다. 이 목록을 작성한 것만으로 운영 완료나 법률 검토 완료로 표시하지 않는다.
