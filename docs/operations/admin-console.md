# 포둥 관리자 사이트

작성일 2026-10-29

## 이번 제공 범위

`/ko/admin` 또는 `/en/admin`에서 별도 관리자 화면을 제공한다. 기존 가족용 하단 메뉴와 구분한다.

- 대시보드: 활동 가족·꾸준히 기록한 가족·함께 기록한 가족, 신규 사용자, 기록 수와 확인할 요청·오류·실패 작업.
- 개발 요청: 상태·종류 필터, 30개씩 추가 조회, 처리 상태·우선순위·내부 메모 수정. 내부 메모는 요청자가 읽을 수 없는 별도 테이블에 보관한다.
- 이용 분석: 7·14·28일 일별 가입·활동 가족·기록 수, 최근 28일 신규 가족의 아이 등록·첫 기록·다른 날짜 재사용, 기록 유형 집계.
- 사용자·가족: 계정 상태와 가족 인원·아이 수 등의 운영 메타데이터. 비공개 일기와 아기 사진을 열람하는 기능은 제공하지 않는다.
- 동네 현황: 지역별 중복 제외 신청 가족 수와 개방 상태. 신청 기록이 있는 최대 100개 지역을 표시한다.
- 운영 상태: 식사 푸시 설정·예약 상태, 성공 건수, 사진 정리·탈퇴 처리 대기, 최근 실패 작업 50건, 서비스 화면 오류와 해결 표시.
- 작업 이력: 관리자 권한 지정·변경·해제, 요청 처리와 오류 해결 이력.

광고와 외부 분석 SDK는 이번 작업에 포함하지 않는다. 외부 서비스 가입·분석 키 없이 서울 Supabase 집계를 사용할 수 있다. Sentry/PostHog를 연결한 것으로 간주하지 않는다. 작업 상태 조회는 실제 알림 재발송이나 계정 삭제 작업을 실행하지 않는다.

## 직접 할 설정

### 최초 운영자 계정 지정

1. 포둥에서 평소 사용할 소셜 계정으로 로그인하고 기본 가입을 마친다.
2. **서울 프로젝트**의 Supabase → Authentication → Users에서 해당 계정의 **User UID**를 확인한다. 문의 이메일과 카카오 계정의 이메일이 일치한다고 가정하지 않는다.
3. 운영 DB의 SQL Editor에서 아래의 UUID를 자신의 UID로 바꿔 실행한다. 앱이나 브라우저의 공개 키로는 실행할 수 없다.

```sql
insert into public.service_admins (user_id, role)
select id, 'owner'
from public.profiles
where id = '본인의-User-UID'::uuid
  and consented_at is not null
on conflict (user_id) do nothing;
```

반영된 계정은 아이 이름 메뉴 → 서비스 정보에 관리자 사이트 링크가 표시된다. 직접 주소로 접속해도 된다. 가족관리자나 커뮤니티 운영자는 서비스 관리자가 아니다. 관리자를 해제하려면 운영 DB에서 해당 `service_admins` 행을 삭제한다. 권한 변경은 감사 이력에 남는다.

### 접속

관리자로 지정한 소셜 계정으로 로그인한 다음 `/ko/admin` 또는 `/en/admin`에 접속한다. 2026-10-29 사용자 요청으로 관리자 2단계 인증 요구를 해제했다. QR 등록·인증번호 입력 없이 대시보드가 열린다. 예전 `/admin/verify` 주소는 권한 확인 후 대시보드로 이동한다.

운영 HTTPS 주소가 준비되면 해당 주소에서 이용한다. 운영자용 별도 도메인은 지금 필수가 아니다.

## 접근 제어

모든 관리자 데이터 RPC는 현재 계정의 `service_admins` 등록과 활성 계정·기본 가입 동의 상태를 DB에서 검사한다. MFA 요소나 JWT `aal2`는 요구하지 않는다. 가족 소유권·커뮤니티 운영 권한·사용자가 수정할 수 있는 프로필 값은 관리자 자격으로 사용하지 않는다. 브라우저에는 서비스 비밀키를 제공하지 않는다. 관리자는 내부 메모·오류·감사 테이블을 직접 읽거나 수정할 수 없으며 허용된 RPC만 사용한다.

관리자 페이지는 `private, no-store`, 검색 제외, 외부 참조 URL 차단과 프레임 삽입 차단 헤더를 제공한다. 이미 사용자가 내려받은 화면 사본을 원격으로 회수할 수 있다고 가정하지 않는다.

## 집계 기준과 한계

한국 표준시를 관리 기준으로 사용한다. 활동은 저장된 먹이기·수면·용변·성장·기타 돌봄 기록의 **생성일**을 기준으로 하며, 같은 기록의 수정은 신규 이용으로 중복 집계하지 않는다. 꾸준한 가족은 최근 7일 중 3개 이상 날짜에 기록한 가족이고, 공동 돌봄은 같은 기간 서로 다른 작성자 2명 이상이 기록한 가족이다.

신규 가족 흐름의 재사용은 서로 다른 날짜에 기록한 가족이다. 정확한 D1/D7 유지율이나 방문 대비 전환율로 표기하지 않는다. 현재 보관 중인 자료에서 계산하므로 삭제한 자료와 탈퇴 계정은 지표에서 제외된다. 화면 클릭·세션 녹화·GPS·광고 식별자·외부 서비스 전송을 수집하지 않는다.

## 오류와 작업 처리

서비스 오류는 미리 정의한 화면 종류·오류 코드·숫자형 오류 식별자만 수집한다. 원본 오류 메시지·폼 값·전체 URL·쿠키·아기 이름·일기·사진은 저장하지 않는다. 로그인 계정별 시간당 최대 20건이며 30일 뒤 정리한다. 운영자 작업 이력은 365일 뒤 정리한다. 관리자 메모는 해당 요청·계정 삭제와 함께 삭제한다.

DB 자체가 중단된 경우 이 DB 기반 오류 수집도 작동하지 않을 수 있다. 전체 장애 감시와 외부 오류 추적은 별도 연동 대상이다. 푸시의 예약이 활성이라는 표시는 실제 단말 수신 성공을 뜻하지 않는다. 실패한 삭제 작업을 처리하려면 기존 운영자용 작업 처리기와 `docs/operations/data-and-backup.md` 절차를 사용한다. 실제 운영 발송·삭제 검증은 테스트 자료 검증과 구분한다.
