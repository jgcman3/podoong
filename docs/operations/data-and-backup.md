# 데이터 삭제·백업 운영

작성일: 2026-10-12

## 삭제 처리

`/ko/data`, `/en/data`에서 아이 기록 전체 JSON 내보내기, 아이 삭제, 가족 소유권 이전, 계정 삭제를 제공합니다. 삭제에는 5분 이내 OAuth/비밀번호 재인증과 `DELETE CHILD` 또는 `DELETE ACCOUNT` 입력이 필요합니다. 소유권 이전 문구는 `TRANSFER OWNER`입니다. 이메일은 식별자가 아닙니다.

계정 요청 전에 서버가 관리자 자격증명으로 동일 프로젝트의 해당 Auth 사용자를 확인하고 2분 유효 허가를 발급합니다. 키 누락·프로젝트 불일치 시 앱 데이터는 삭제하지 않습니다. 요청 성공 시 접근권한과 프로필·커뮤니티 게시물·투표를 즉시 제거하며, 남은 가족의 기록은 작성자 식별자를 비웁니다. 다른 구성원이 있는 유일한 소유자는 먼저 소유권을 이전해야 합니다.

서버 전용 `SUPABASE_SECRET_KEY` 또는 `SUPABASE_SERVICE_ROLE_KEY`를 사용합니다. 브라우저 공개 변수에 넣지 않습니다. 기존 로컬 서비스 키를 호스팅 프로젝트에 재사용하지 않습니다.

운영자는 데이터 화면에서 처리하거나 명시적으로 프로젝트를 지정해 실행합니다.

```sh
OPERATIONS_SUPABASE_URL=<project-url> OPERATIONS_SUPABASE_SECRET_KEY=<server-secret> node scripts/process-operations.mjs
```

키를 명령 기록에 남기지 않도록 실제 운영에서는 보안 환경변수 관리 도구로 주입합니다. 작업자는 사진 삭제 확인 후 Auth 사용자를 삭제합니다. 5분 임대와 최대 10회 재시도, 상태 이력을 저장합니다. 실패 작업은 원인 수정 후 운영자가 상태/시도 횟수를 점검하고, 임대 만료(5분) 후 화면의 재시도 버튼으로 시도 횟수를 초기화하여 재개합니다. 로그에는 본문·이름·사용자 ID·키를 출력하지 않습니다. 사진 삭제 큐와 24시간 이상 미등록 객체 청소를 같은 작업에서 처리합니다.

## 백업·복원 검증

`node scripts/verify-local-restore.mjs`는 **supabase_db_podung 컨테이너만** 대상으로 public/auth/storage/extensions를 메모리 덤프한 뒤 임의의 새 DB로 복원합니다. 원본 DB와 환경설정을 변경하지 않으며 핵심 테이블 건수, 정책·함수·제약 수를 확인하고 새 DB만 제거합니다. 이 로컬 검증은 `--no-owner --no-acl`을 사용하므로 역할·GRANT 복원은 검증하지 않습니다. 운영 복원에서는 역할/권한을 마이그레이션으로 재적용하고 사용자별 접근을 별도로 검증합니다. 관리자 역할 및 확장 의존성으로 실패하면 스크립트 오류를 확인하고 원본에 복원하지 않습니다.

DB 백업은 Storage 객체의 **실제 파일 바이트를 포함하지 않습니다**. 운영 백업은 비공개 버킷 객체 경로·크기·체크섬 목록을 생성하고 별도 암호화 저장소에 파일을 복제해야 합니다. 복원은 격리 프로젝트에서 DB → 버킷 설정 → 객체 업로드 → 목록/체크섬 비교 → 비인가 접근 차단 → 샘플 다운로드 순서로 검증합니다. 실제 호스팅 백업/복원과 객체 복제는 아직 검증되지 않았습니다.

## 사고·롤백

사고 시 삭제 작업자를 중지하고 요청 시간·작업 상태 등 최소 메타데이터만 확보합니다. 격리 환경에 백업을 복원한 뒤 RLS, 권한, 파일 접근, 핵심 기록을 확인하고 전환합니다. 운영 DB에 검증되지 않은 덤프를 덮어쓰지 않습니다. 마이그레이션 후 데이터 변경이 있다면 코드만 롤백하거나 보정 마이그레이션을 사용합니다.

백업 보존기간·복원 목표시간·책임자·비용은 파일럿 전에 운영자가 확정해야 합니다. 삭제된 사용자 데이터는 보존 백업에 만료일까지 남을 수 있으므로 고지하고, 복원 시 삭제 작업 이력을 재적용하여 삭제 데이터가 서비스에 다시 노출되지 않도록 합니다.

## 돌봄 사진 정리

`012`의 `child-care-photos`는 비공개 버킷입니다. 성장 기록·사진·아이·업로더 계정 삭제 시 `child_photo_cleanup`에 파일 경로가 등록됩니다. 운영 작업자는 커뮤니티 사진과 돌봄 사진을 모두 정리한 뒤 계정 삭제를 진행합니다. 메타데이터 삭제 즉시 사용자 조회는 차단되며 실제 바이트 삭제는 작업자 실행 시 완료됩니다. 24시간 이상 메타데이터가 없는 업로드도 정리 대상입니다. 작업자 예약 실행과 실패 감시를 구성하고 두 비공개 버킷 모두 별도 파일 백업에 포함하십시오. 로컬 복원 검증은 `btree_gist` 확장 의존성과 세 신규 테이블도 검사합니다.
